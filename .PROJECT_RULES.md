# Portfolio Project Rules

## 1. Profile Accuracy

This portfolio represents my real professional background.

- Keep all professional information factual and realistic.
- Do not exaggerate my seniority, responsibilities, achievements, or expertise.
- Do not invent work experience, projects, technologies, certifications, or responsibilities.
- Do not describe me as a Senior, Expert, Architect, Lead, or similar unless explicitly supported by the existing profile data.
- Full-stack web development is my main professional experience.
- Dynamics AX / Power Platform is a developing career direction supported by current part-time professional experience.
- Clearly distinguish professional experience from learning or future career direction.

## 2. Content

- Treat existing profile data as the source of truth.
- Preserve factual information unless I explicitly request a change.
- Do not rewrite professional history just to make it sound more impressive.
- Prefer clear, concise and natural language.
- Avoid unnecessary marketing language and exaggerated claims.

## 3. Design Principles

- Clean, professional and modern portfolio.
- Prioritize readability over visual effects.
- Use clear visual hierarchy.
- Use sufficient font size, line height and whitespace.
- Avoid excessive animations and decorative elements.
- Keep the design consistent across all pages.
- The website should work well on desktop, tablet and mobile.

## 4. Development Principles

- Inspect the existing implementation before making changes.
- Reuse existing components and styles whenever possible.
- Make the minimum necessary changes.
- Do not rewrite working functionality without a clear reason.
- Do not add new dependencies unless necessary.
- Do not change routes or application architecture unless explicitly requested.
- Do not modify unrelated pages or components.

## 5. Task Scope

When I give a specific task:

- Work only within the requested scope.
- Do not make unrelated improvements.
- Do not redesign other pages unless explicitly requested.
- Do not change content when the task is only about UI/design.
- If an existing implementation already solves the problem, improve it rather than rebuilding it.

## 6. Quality

Before considering a task complete:

- Check desktop layout.
- Check mobile responsiveness when relevant.
- Check for broken styles or functionality.
- Keep the implementation consistent with the existing project.
- Briefly summarize what was changed.
